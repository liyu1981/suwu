# Extension Tile — Feature Plan

> **Status:** Implemented (v1). `pkg/extension`, `/gqjs/ext/<id>`,
> `/api/extensions`, the `extension` tile plugin and the App Menu id selector
> are built and tested.
> **v2:** package.json metadata (no `meta.json`) and extension APIs under
> `/gqjs/api/<id>/<path>` — see `docs/EXTENSION_API_PLAN.md`.
> **Goal:** Add an `extension` tile plugin — a blank container tile that hosts a
> page generated by a gqjs script. Extensions are small JS programs run by the
> `suwu gq` runtime **in a separate process**, so a crash or runaway script
> cannot take down the Suwu server.

Reference implementations: `.opencode/skills/suwu-tile-plugin-design/SKILL.md`,
`frontend/src/wm/plugins/diff.tsx` (iframe plugin), `frontend/src/routes/XDisplayPage.tsx`
(CommonTileContainer route), and `pkg/gqjs` + `cmd/Suwu/gq.go` (the runtime).

---

## 1. The model

An **extension** is a single JavaScript file that returns an HTML page. It runs
on demand, per request, through `suwu gq`:

```
Browser (Suwu tab)
  TilingWM pane
    └── <iframe src="/extension?pane=P1&id=eye">          ← trusted Suwu page
          ExtensionPage (CommonTileContainer)
            └── <iframe src="/gqjs/ext/eye?pane=P1" sandbox>  ← untrusted generated doc
                                     │
                                     ▼  HTTP GET
                              Go server  ──spawn──►  suwu gq --result-file …
                                                        │ (separate process)
                                                        ▼
                                              gqjs script handler(input)
                                                        │
                                              { contentType, body: "<!doctype html>…" }
```

Two iframes on purpose:

- **`/extension`** is a normal Suwu route page. It gives the tile the standard
  lifecycle for free (session state, focus, shortcut relay, background, zoom)
  via `CommonTileContainer`.
- **`/gqjs/ext/<id>`** is the extension's own document, served from a separate
  origin-ish boundary (sandboxed iframe) so untrusted extension HTML/JS cannot
  touch Suwu's DOM, storage, or the parent window.

The plugin itself is deliberately "blank": it just wires `id` + params into the
two URLs. All behavior lives in the extension script.

---

## 2. End-to-end flow

1. User opens a **config tile** — a named custom app in the App Menu that
   targets `pluginId: "extension"` with `params: { id: "eye", … }`.
2. `extension.tsx` renders `<iframe src="/extension?pane=P1&id=eye&…">`.
3. `ExtensionPage` reads `id`/params from `window.location.search`, wraps the
   tile in `CommonTileContainer`, and renders the inner
   `<iframe src="/gqjs/ext/eye?pane=P1&…" sandbox="allow-scripts …">`.
4. The browser GETs `/gqjs/ext/eye`; the server:
   a. validates the extension id and auth;
   b. builds the `input` JSON (action/id/pane/method/url/query);
   c. runs `suwu gq --result-file <tmp> --input <json> --root /ext=<dir> <script>`
      as a **child process** with a deadline;
   d. reads the JSON result and writes the HTML response with a scoped CSP.
5. The generated document runs in the sandboxed iframe (e.g. the eye follows
   the pointer entirely client-side).

If `id` is missing, `ExtensionPage` shows a short hint telling the user to
configure the tile (no in-tile picker) — see §5.2/§5.4.

## 3. Extension contract

### 3.1 Location and layout

```
<dataDir>/extensions/            # dataDir = $SUWU_VAR or ~/.suwu
  eye/                           # id = "eye"
    package.json                 # metadata (required; suwu object: api/static/net)
    index.js                     # entry point (hard-coded)
    public/                      # static assets (suwu.static) — served WITHOUT auth
  chart/
    package.json
    index.js
    public/
```

- **id** is the directory name, validated against
  `^[a-z0-9][a-z0-9_-]{0,63}$` (no slashes, no dots) — the primary
  path-traversal defense.
- **`index.js`** is the entry point and is **hard-coded**; there is no `main`
  field in the metadata.
- **`package.json`** is required; npm-style fields stay at the top level,
  Suwu specifics live under the `suwu` object:
  ```json
  {
    "name": "Eye",
    "description": "An eye that follows the pointer",
    "suwu": {
      "params": [
        { "key": "size", "label": "Size", "description": "Eye radius in px", "defaultValue": "120" }
      ]
    }
  }
  ```
  `name` defaults to the directory id when omitted; `description` and
  `suwu.params` are optional. `params` documents the extension's launch
  params for the picker; arbitrary query params are still passed through
  regardless. `suwu.api` registers API routes — see
  docs/EXTENSION_API_PLAN.md. There is no `meta.json` fallback.
- **`suwu.static`** declares a directory of client assets served under
  `/gqjs/static/<id>/` — deliberately **unauthenticated** (opaque-origin
  module fetches carry no credentials), so files there must never contain
  secrets. See docs/EXTENSION_API_PLAN.md §2.8.
- The extension directory is also the extension's `/ext/<id>` read-only root,
  so it can bundle assets next to `index.js`.
- Nothing is seeded automatically: installable examples live in
  `examples/extensions/` and are copied here by the user (see §6).

### 3.2 Invocation

The script is run by `suwu gq` with:

| Flag | Value |
|---|---|
| `--input-file` | temp file holding `{"action":"render","id":"eye","pane":"P1","method":"GET","url":"/gqjs/ext/eye","query":{…},"params":{…}}` |
| `--root` | `/ext=<extensionsDir>` (read-only) |
| `--ro` | yes |
| `--timeout` | `5s` (configurable) |
| `--result-file` | temp file the server reads the JSON result from |
| positional | absolute path to `<extensionsDir>/<id>/index.js` |

### 3.3 Result contract

`handler(input)` may return:

- a **string** → used verbatim as `text/html`; or
- an **object**:
  ```js
  return {
    status: 200,                       // optional, default 200
    contentType: "text/html; charset=utf-8", // optional, default text/html
    body: "<!doctype html>…",          // required
  };
  ```
  `{ html: "…" }` is accepted as shorthand for `{ body: html }`.

Non-2xx `status` is honored. Missing/invalid result ⇒ `500` with a minimal
error page (never the raw stack to the browser; log it server-side).

### 3.4 `index.js` sketch (example lives at `examples/extensions/eye/index.js`)

```js
function handler() {
  const html = `<!doctype html><html><head><meta charset="utf-8">
<style>html,body{margin:0;height:100%;background:#111}canvas{display:block}</style>
</head><body><canvas id="c"></canvas><script>
const c = document.getElementById('c'), x = c.getContext('2d');
let mx = innerWidth/2, my = innerHeight/2;
addEventListener('mousemove', e => { mx = e.clientX; my = e.clientY; });
function frame(){
  c.width = innerWidth; c.height = innerHeight;
  // …draw sclera, iris aimed at (mx,my), pupil, highlight…
  requestAnimationFrame(frame);
}
frame();
<\/script></body></html>`;
  return { body: html };
}
```

The mouse tracking is pure client-side JS in the returned page — gqjs runs once
to produce the document, not per mouse move.

## 4. Backend

### 4.1 `pkg/extension` — registry

New package owning discovery and invocation inputs:

- `Dir(dataDir) string` → `<dataDir>/extensions`.
- `List(dir) ([]Extension, error)` — scan subdirectories, require `index.js`,
  read `package.json`, and return sorted
  `{ ID, Name, Description, Params, API, Dir, Entry }`.
- `Resolve(dir, id) (Extension, error)` — validate the id, require
  `<id>/index.js` and `<id>/package.json` (no legacy `meta.json` fallback),
  reject malformed `suwu.api` registrations, and confirm the resolved
  directory stays inside `dir` (`filepath.EvalSymlinks` + prefix check).
- `MatchAPI(routes, path)` + `(Extension).HandlerPath(handler)` — ordered
  first-match route selection and traversal-safe handler resolution for the
  API surface (docs/EXTENSION_API_PLAN.md).
- `idRe` validation and unit tests.

### 4.2 `pkg/server/extension.go` — the route

- `GET /gqjs/ext/<id>` → `handleExtension`.
- `GET/POST/… /gqjs/api/<id>/<path>` → `handleExtensionAPI`
  (pkg/server/extension_api.go, see docs/EXTENSION_API_PLAN.md).
  - Method check (GET only) + auth (§4.6).
  - `extension.Resolve(dir, id)`; 404 on unknown.
  - Build `input` JSON from the request (query params → `query`, all → `params`).
  - Run the child process via an injectable `ExtensionRunner` interface
    (default: real `exec`; tests: stub) — see §4.5.
  - Parse the `--result-file` JSON, render the response, set headers (§4.7).
  - Error mapping: unknown id → 404; timeout → 504; script error / bad result →
    500; success → the extension's status.
- `GET /api/extensions` → `handleExtensionsList` (auth via `validateRequest`),
  returns `{ "extensions": [ { id, name, description } ] }`. Consumed by the
  App Menu config editor to populate the extension `id` selector (§5.4), not by
  the tile.
- Register both in `Server.route`.

### 4.3 `suwu gq --result-file <path>`

Small addition to `cmd/Suwu/gq.go` (and its usage text): on success, write
`res.JSON` to `<path>` (0644). `--print-result` is unchanged. This gives the
server a reliable machine-readable result without parsing stdout (which also
carries `console.log` output). Add a test.

### 4.4 Process isolation

The server invokes **its own binary**:

```go
exe, _ := os.Executable()
cmd := exec.CommandContext(ctx, exe, "gq",
    "--timeout", "30s",
    "--result-file", resultPath,
    "--input", string(inputJSON),
    "--root", "/ext="+extDir,
    "--ro",
    scriptPath)
cmd.Env = []string{"PATH=" + os.Getenv("PATH"), "HOME=" + os.Getenv("HOME")}
```

- A fresh process per render ⇒ a JS panic, OOM, or wazero hard-kill cannot
  affect the server.
- **Timeout follows the PHP rule: 30s** (`max_execution_time`), overridable via
  `SUWU_EXTENSION_TIMEOUT` (useful for tests). `CommandContext` uses
  `timeout + 1s` as the backstop; gq's own `--timeout` normally fires first and
  yields a clean exit code `2`.
- **Concurrency cap** (semaphore, e.g. 4) bounds the number of child processes.
- stdout/stderr are captured to a bounded buffer for logging only.

### 4.5 Auth

`/gqjs/ext/<id>` is an iframe navigation, so it cannot send an HMAC header. The
browser already holds the `suwu_token` cookie (`Path=/`, `SameSite=Lax`), so the
handler authenticates by reading that cookie and validating it through the
existing token path (`auth.ValidateAPIRequest` with the cookie value as the
query token). The query-token fallback (`?token=`) also works, matching
`/api/file`. `/api/extensions` uses the normal `s.validateRequest`.

### 4.6 Response headers / CSP

`/gqjs/ext/<id>` is dynamic HTML, so it sets its own headers (the global `csp`
constant only applies to `.html` static assets):

```
Content-Type: <extension contentType or text/html; charset=utf-8>
Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline';
                         style-src 'unsafe-inline'; img-src data: blob:;
                         font-src data:; connect-src 'self';
                         frame-ancestors 'self'
X-Content-Type-Options: nosniff
Cache-Control: no-store
```

`'unsafe-inline'` is required because extension pages are self-contained
documents. `frame-ancestors 'self'` allows the same-origin `/extension` page to
frame it while blocking third-party framing. Note: the global static CSP has no
`frame-ancestors` conflict here because this route sets its own.

### 4.7 Focus & keyboard relay (injected server-side)

The nesting breaks two things that every other tile gets for free:

- **Focus.** Ancestor frames do **not** re-fire `window.focus` when focus
  descends into a child frame — only the innermost document does. So
  `CommonTileContainer`'s `focus → pane-focus` never fires for an extension
  tile and the WM never marks it focused (verified in a headless Chromium
  harness: the inner document fired `focus`/`focusin` while the middle window
  fired nothing and the shell only got a `blur`).
- **Keyboard.** Key events stop at document boundaries, so Alt WM shortcuts
  and Ctrl space-switching typed inside the extension never reach the tile page
  or the shell.

The tile page also **cannot** reach into the extension (`contentDocument` is
`null` under sandbox), and `srcdoc`/`blob:` would inherit the `/extension`
page's CSP (`script-src 'self'`) and block every inline script. The only place
we still control the response headers is the HTTP response itself, so the relay
is injected there.

**Server (`injectExtensionRelay`)** — inserts a `<script data-suwu-ext-relay>`
immediately before `</body>` (else `</html>`, else appended), only when the
content type is `text/html`, and only if the marker is absent (idempotent). It:

- posts `ext-focus` **once per focus episode** (window `focus` + first
  `focusin`, reset only on window `blur`, so moving between elements doesn't
  spam); on load it announces only if `document.hasFocus()` is already true;
- posts `ext-key` with the raw key + modifiers;
- swallows the browser defaults for those two families so history/tab switching
  can't fire from inside the tile (`altKey && !ctrl && !meta`, plus
  `ctrlKey && !alt && !meta` for Tab / digits).

**Tile page (`ExtensionPage.tsx`)** — the middle hop. Accepts a message only
when `e.source === innerRef.current.contentWindow`, then re-states it in the
shell's vocabulary: `ext-focus → {type:'pane-focus', pane: <its own paneId>}`
and `ext-key → {type:'wm-key', key, altKey, …}`. The extension never gets to
name the pane or the action.

**Shell (`TilingWM.tsx`)** —

- `isDirectTileFrame(e.source)` gates `pane-focus`, `wm-key`, `wm-shortcut`,
  `wm-close-pane` and `wm-open-file`: only a direct child iframe carrying
  `data-pane` may drive tile state. A direct hop from an extension
  (`window.parent.parent`) fails this check and is dropped.
- `wm-key` synthesizes a `KeyboardEvent`, runs `wmAction(...)` for Alt
  shortcuts, else falls through to `handleSpaceKey(...)` — the space-switching
  logic extracted from the window `keydown` listener so there is exactly one
  implementation serving both paths.

**Verified** (headless Chromium, real served HTML): relay present exactly once,
`focus → ext-focus → pane-focus(PANE-42) → trusted:true`, and
`Alt+ArrowLeft → wm-key → trusted:true`. The shell's `wmAction`/`handleSpaceKey`
handling and `ExtensionPage`'s listener are covered by `tsc` + a harness that
mirrors them (the repo has no browser test runner).

**Trade-off:** because Alt/Ctrl defaults are swallowed preemptively inside the
extension, an Alt-combo that is *not* a WM shortcut is also inert there. That
matches every other tile's behavior for matching combos and is the price of
stopping Alt+Left from navigating the SPA away.

### 4.8 Storage bridge (`ext-store`)

Sandboxed extension frames have an **opaque origin**, and browsers deny all
web storage to opaque origins (localStorage and IndexedDB both throw
`SecurityError`) — so a client-side extension like `note` persists through
the trusted `ExtensionPage` instead:

1. The child posts `{type:'ext-store', op:'get'|'set', key, rid, value?}`.
2. The page accepts it only from *its own* inner frame (the same `e.source`
   check that gates the focus/key relay), validates `key` against
   `[A-Za-z0-9._-]{1,64}`, and forces the full key to
   `suwu:ext/<ext-id from this pane's own URL>/<key>` — the child only ever
   chooses the suffix, so it can never reach another extension's keys, app
   settings, or the session.
3. Values are capped at 512 KB JSON-serialized; storage is the page's own
   IndexedDB (`suwu-extension-ext`, store `kv`).
4. The page always answers `{type:'ext-store-result', rid, ok, value?,
   error?}` (`error` is the DOMException name, e.g. `QuotaExceededError`);
   the child times out after 3s and degrades to in-memory operation with a
   status line.

## 5. Frontend

### 5.1 Plugin — `frontend/src/wm/plugins/extension.tsx`

```tsx
registerTilePlugin({
  id: 'extension',
  get label() { return i18n.t('plugin.extension') },
  get description() { return i18n.t('plugin.extensionDesc') },
  supportedParams: [
    { key: 'id', label: 'Extension id', description: 'Extension to load (e.g. eye)' },
  ],
  render: (paneId, context) => {
    const p = new URLSearchParams({ pane: paneId });
    if (context?.params) for (const [k, v] of Object.entries(context.params)) p.set(k, v);
    return <iframe src={`/extension?${p}`} title={`extension-${paneId}`}
                   data-pane={paneId} className="h-full w-full border-0 bg-transparent" />;
  },
});
```

All `params` are forwarded to `/extension`, and the page passes them on to
`/gqjs/ext/<id>`. The tile is meant to be driven by a **config tile** (App Menu
custom app): the user picks `id` and adds any extra params there. See §5.4.

### 5.2 Route page — `frontend/src/routes/ExtensionPage.tsx`

- `setPageTransparent()` on mount.
- Wrap in `<CommonTileContainer zoomAtom={extensionZoomAtom} noPadding>`.
- Read `id` + extra params from `window.location.search`.
- If `id`: render the inner iframe
  `<iframe src={`/gqjs/ext/${id}?${p}`} sandbox="allow-scripts allow-pointer-lock allow-popups allow-popups-to-escape-sandbox" />`
  (`allow-same-origin` is deliberately **omitted** → opaque origin). All extra
  params are appended to `p`. The render response carries the same tokens as a
  CSP `sandbox` directive, so a direct tab or escaped popup is re-sandboxed.
- If no `id`: render a short empty-state hint ("Configure this tile with an
  extension id in the App Menu"). **No in-tile picker** — selection happens in
  the config editor (§5.4).
- Optional: relay `pane-focus` from the inner document if the extension wants
  focus reporting (future).

### 5.3 Registration

- `frontend/src/wm/TilingWM.tsx`: `import './plugins/extension';`
- `frontend/src/router.tsx`: add `extensionRoute` (`/extension`, parent
  `rootRoute`) to `rootRoute.addChildren([...])`.
- `frontend/src/store/zoom.ts`: `extensionZoomAtom`.
- `frontend/src/wm/appIcons.ts`: `extension: { bg: 'bg-teal-500/20', text: 'text-teal-400', letter: 'E' }`.
- `frontend/src/locales/en.json` + `zh_CN.json`: `plugin.extension`,
  `plugin.extensionDesc`.
- `frontend/vite.config.ts`: add `'/gqjs': { target: demoTarget }` to
  `server.proxy` so `pnpm dev:web` reaches the backend.

### 5.4 Config-tile integration (App Menu)

The extension tile is a **base for config tiles**: users compose a named custom
app in the App Menu that targets `pluginId: "extension"` with
`params: { id: "eye", … }`. There is no extension picker inside the tile — the
selection lives in the config editor.

- `AppMenuView.tsx` already renders a text row per param (`ParamRow`). Add a
  special case: when the active plugin is `extension` and the key is `id`,
  render a `<select>` of available extensions instead of a free-text input.
- Options come from a new `useExtensions()` hook
  (`frontend/src/lib/extensions.ts`) that fetches `GET /api/extensions` via
  `authFetch` once and caches the result.
- **Extra params stay first-class.** Users add arbitrary keys with the existing
  "+ Add parameter" control; every key is forwarded to the extension unchanged.
- If the list fetch fails, the `id` row falls back to the plain text input so
  the editor never hard-depends on the endpoint.

## 8. Security

| Concern | Mitigation |
|---|---|
| Path traversal via `id` | Strict id regex; resolve + symlink-check inside the extensions dir. |
| Server crash from a bad script | Separate `suwu gq` process per render; concurrency cap; `CommandContext` kill. |
| Runaway CPU / infinite loop | gqjs deadline (`--timeout`, default 30s) + process kill backstop. |
| Memory bomb | gqjs `MemoryLimit`/`MaxStackSize` defaults (64 MiB / 1 MiB). |
| Output flood | gqjs `MaxOutputBytes` (1 MiB); server reads the result file, not stdout. |
| Untrusted HTML/JS in the app | Nested iframe sandboxed **without** `allow-same-origin`; scoped CSP with `default-src 'none'`, plus the matching CSP `sandbox` guard on the render response so direct tabs and escaped popups are re-sandboxed. |
| Unauthenticated execution | `/gqjs/ext/<id>` and `/api/extensions` require the session token; `/gqjs/api/<id>/…` requires that extension's derived token (session token rejected). See EXTENSION_TOKEN_SCOPING_PLAN.md. |
| Public static assets | `/gqjs/static/<id>/…` is deliberately unauthenticated (opaque-origin module fetches carry no credentials) — extension `public/` files must never contain secrets; see EXTENSION_API_PLAN.md §2.8. |
| FS access | Extension process gets only `/ext` (read-only) by default. |

## 10. Locked decisions

1. **Render-only.** No dynamic/RPC channel in this stage, and no data fetching
   either: the extension page is served into a sandboxed iframe **without**
   `allow-same-origin`, so it runs on an opaque origin and a `fetch` to
   `/api/*` is blocked by CORS (the API sets no `Access-Control-Allow-Origin`).
   Extension pages must therefore be self-contained documents.
2. **Extensions dir.** `<dataDir>/extensions/`, i.e. the Suwu data-dir prefix
   (`$SUWU_VAR` or `~/.suwu`) plus `extensions`.
3. **Directory layout.** Each extension is a directory: `package.json`
   (metadata) and `index.js` (hard-coded entry point).
4. **Metadata.** `package.json` is required; `name` defaults to the id,
   `description` and `suwu.params` are optional.
5. **Timeout.** 30s per render (PHP `max_execution_time` rule), overridable via
   `SUWU_EXTENSION_TIMEOUT`; max 4 concurrent child processes.
6. **No in-tile picker.** The extension tile is the base for config tiles; the
   extension `id` is chosen in the App Menu custom-app editor (§5.4).
7. **List endpoint.** `GET /api/extensions` exists to populate that editor's
   `id` selector (and future tooling), not the tile.
8. **Extra params.** Arbitrary params configured on the custom app are passed
   through to the extension (`input.query` / `input.params`).
9. **Default off.** The `extension` plugin declares `defaultHidden`, so a fresh
   install does not advertise it in the tile app selector; enabling it in App
   Menu settings records an explicit `shownApps` entry that persists.

### Remaining minor defaults (proposed)

- `package.json` schema as shown in §3.1.
- Concurrency cap constant `4`; example extensions live in
  `examples/extensions/` (nothing seeded).

- A long-lived worker pool (each render is a fresh process).
- Extension-provided tile toolbar controls, session state, or parent-window IPC.
- Extension installation/management UI (users place directories by hand).
